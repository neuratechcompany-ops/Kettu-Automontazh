# video-edit — локальный монтажный движок

Ты не смотришь видео. Ты **читаешь** его.

Час видео — это 108 000 кадров (≈162M токенов) или транскрипт с точностью до слова
на 12 КБ. Все монтажные решения принимаются по тексту; к картинке обращаешься
точечно, когда решение действительно зависит от того, что в кадре.

Снимает пользователь. Твоя работа — **резать и собирать**: выбрать дубли, убрать
мусор, склеить, выровнять звук, вшить субтитры, отдать готовый файл.

## Запуск

```bash
VE=~/.claude/skills/video-edit/scripts/ve
```

**Скилл не содержит кода движка.** `scripts/ve` — тонкий запускатель поверх пакета
`automontazh` (`~/Kettu-Automontazh`, он же
[Kettu-Automontazh](https://github.com/neuratechcompany-ops/Kettu-Automontazh)).
Правка движка делается **в пакете**, здесь — только инструкция. Если пакет не
установлен, запускатель скажет об этом и даст точные команды починки.

Правишь движок — гоняй `$VE selftest` и коммить в репозиторий пакета, не сюда.

Работай из папки с исходниками — движок держит там кэш в `.ve/`.

Проверки: `$VE doctor` — окружение, `$VE selftest` — весь конвейер на синтетическом
дубле (32 шага, ~2 мин). Запускай `selftest` после любой правки движка.

Модели ASR лежат локально, качаются один раз: `$VE pull turbo`.

| модель | размер | скорость | когда |
|---|---|---|---|
| `turbo` | 1.6 ГБ | очень быстро | по умолчанию, годится почти всегда |
| `large` | 3 ГБ | медленнее | плохой звук, сильный акцент, термины |
| `small` / `tiny` | 0.5 ГБ / 75 МБ | мгновенно | черновая раскадровка, отладка |

Если `transcribe` падает на загрузке — это Xet-транспорт HuggingFace виснет на
некоторых сетях. `$VE pull` его обходит; просто повтори команду.

## Быстрый путь: один ролик — одна команда

Если задача обычная («смонтируй мне из этого шортс»), не собирай конвейер руками:

```
$VE shorts FILE.mp4
```

Делает всё разом: расшифровка → автонарезка → авто-грейд по замерам → реврейм по лицу
(сам отключится, если исходник уже вертикальный) → субтитры → громкость → `verify`.
Кладёт результат в `edit/shorts.mp4`, а разметку — в `shorts.json`.

Включено по умолчанию: авто-грейд картинки, голосовой тракт, реврейм, субтитры.
Ключи: `--style chip|hormozi|karaoke|standard|minimal`, `--no-enhance` (не трогать
картинку), `--no-voice` (не трогать звук), `--cards` (счётчики перечисления —
только по явной просьбе), `--fast`, `--lang ru`.

**Дальше правь EDL, а не команду.** Не нравится выбор кусков — редактируй
`shorts.json` и гони `$VE render shorts.json`: исходники уже в кэше, пересборка
занимает секунды.

Ручной конвейер ниже нужен, когда задача нестандартная: несколько исходников,
перебивки, свой порядок кусков, горизонтальный формат.

## Рабочий цикл

1. **`$VE probe .`** — инвентаризация: длительность, разрешение, fps, звук.
2. **`$VE transcribe FILE --lang ru`** — локальный ASR на Metal → `.ve/*.words.json`.
   Кэшируется; повтор бесплатный. Для каждого исходника со звуком.
3. **`$VE pack FILE`** → `.ve/*.transcript.md`. **Прочитай его целиком.** Это твой
   единственный обязательный вход. В нём размечено: `⟨слово⟩` — что срежет
   автонарезка, `⏸2.4s` — мёртвый воздух, `⚠` — низкая уверенность ASR.
4. **`$VE autocut FILE --captions hormozi`** → черновой `edl.json`.
5. **Правь EDL руками.** Это главный шаг и он твой, а не машины: выбрать лучший
   дубль, переставить смысловые блоки, задать грейд и переходы, снять субтитры там,
   где они мешают. Автонарезка — только черновик.
6. **`$VE render edl.json`** → финал. `--dry-run` покажет план без рендера.
7. **`$VE verify edit/final.mp4 --edl .ve/edl.resolved.json`** — обязательно.
   `FAIL` чинишь и перерендериваешь, `warn` объясняешь пользователю.
8. **`$VE frames edit/final.mp4 -n 9`** — контактный лист. Посмотри сам, прежде чем
   отдавать. Приложи его к ответу.

## Жёсткие правила

Это не стиль, это техника. Нарушение слышно или видно на выходе.

1. **Рез только по границам слов.** Никогда не режь посреди слова. `render --snap`
   (по умолчанию 0.25 с) подтягивает рез к ближайшей границе, сохраняя воздух.
2. **30 мс фейд на каждом стыке звука.** Иначе щелчок. Ставится автоматически, не отключай.
3. **Воздух на склейке: 0.08 с до первого слова, 0.14 с после последнего.** Рез
   впритык съедает согласные и звучит рвано.
4. **Звук всегда паддится (`apad`).** Если у исходника аудиодорожка короче видео —
   а это очень частый случай — без этого `-shortest` молча срежет хвост фильма.
5. **Длительность клипа квантуется в целые кадры.** Иначе на конкатенации копится
   рассинхрон.
6. **Порядок видеофильтров:** геометрия (scale/pad/crop) → грейд → шарп → fps → format.
   Грейд до масштабирования даёт другой результат, шарп до масштабирования — мыло.
7. **Порядок аудио:** resample → denoise → скорость → apad → фейды → loudnorm.
8. **Громкость нормализуется двухпроходным `loudnorm` в -16 LUFS, true peak -1.5 dBTP.**
   Однопроходный качает громкость на паузах. Для YouTube -14, для Instagram/TikTok -14,
   для подкаста -16.
9. **Смена скорости — через `rubberband`**, не `atempo`: сохраняет высоту голоса.
10. **Чётные размеры холста.** h264 не примет нечётные.
11. **Нельзя удалять слово посреди фразы косметически.** Удаление слова = реальный
    рез, который разрывает клип. Движок так и делает; не имитируй удаление,
    расширяя диапазон.
12. **Ничего не отдавай без `verify`.** Дрейф длительности, клиппинг, чёрные кадры,
    рассинхрон A/V ловятся только там.

## Что автонарезка делает сама

- **Твёрдые паразиты** (`э`, `ээ`, `эм`, `ммм`, `um`, `uh`, `hmm`) — чистое мычание,
  режет всегда.
- **Зачины** (`ну`, `вот`, `короче`, `значит`, `так`, `слушай`, `so`, `well`, `okay`) —
  режет, когда перед ними пауза ≥0.2 с, то есть они открывают фразу. Фраза при этом
  начинается со следующего, настоящего слова — склейка чистая.
- **Спорные** (`это`, `типа`, `а`, `и`, `блин`, `like`, `just`) — режет, только если
  пауза ≥0.2 с **с обеих сторон**. В «Привет, **это** тест» пауза лишь спереди, и
  слово обязано выжить: вырезать его — значит сломать фразу.
- **Повторные дубли**: если фраза из 3+ слов сказана дважды подряд в пределах 25 с —
  первый заход выбрасывается, остаётся последний. Это стандартная модель съёмки
  «сбился — переснял».
- **Речевые тики из нескольких слов** — та же двухуровневая осторожность:
  «так сказать», «что называется» режутся везде; «на самом деле», «то есть»,
  «как бы», «по сути», `you know`, `i mean` — **первое вхождение остаётся, все
  последующие вырезаются**. Один раз это речь, второй — уже тик.
- **Мёртвый воздух** длиннее `--max-gap` (0.55 с).

Отключается: `--keep-fillers`, `--keep-retakes`, `--keep-phrases`.

Всё остальное, что повторяется, движок только **показывает**:

```
$VE tics FILE      # список повторов с таймкодами и пометкой «режется / решай сам»
```

Риторический повтор — приём, а не запинка. «Про ИИ, а именно про ИИ в исполнении
агентов» вырезать нельзя: развалится фраза. Такое решает человек, правя EDL.

Не доверяй автонарезке слепо: сверься с `transcript.md` и поправь EDL.

## EDL

```json
{
  "version": 1,
  "output": "edit/final.mp4",
  "canvas": {"w": 1920, "h": 1080, "fps": 30},
  "audio": {"loudnorm": true, "target_lufs": -16, "fade_ms": 30, "denoise": false},
  "grade": "neutral",
  "fit": "pad",
  "captions": {"enabled": true, "style": "hormozi"},
  "clips": [
    {"src": "/abs/take1.mp4", "in": 12.30, "out": 18.75},
    {"src": "/abs/take1.mp4", "in": 41.10, "out": 47.02,
     "grade": "cinematic", "speed": 1.0, "captions": false,
     "transition": {"type": "fade", "dur": 0.4}}
  ]
}
```

- `grade`: `none · neutral · clean · cinematic · warm · cool · punch · bw`
  (на клипе перекрывает глобальный).
- `fit`: `pad` (леттербокс, ничего не теряется) · `crop` (заполнить, режет края).
- `speed`: 0.25–4.0, высота голоса сохраняется.
- `transition` на клипе — переход **перед** ним; `type` — любой из `xfade`
  (`fade`, `wipeleft`, `slideup`, `dissolve`, …). Переходы переводят сборку на
  медленный путь, ставь их точечно.
- `captions: false` на клипе — снять субтитры с этого куска.
- `vf` / `af` на клипе — сырая строка ffmpeg-фильтров, если нужно нештатное.

### Перебивка (b-roll)

`v_src` + `v_in` берут **картинку** из другого файла, оставляя **звук** основного
дубля. Это и есть перебивка: человек продолжает говорить, а на экране другое.

```json
{"src": "/abs/take1.mp4", "in": 12.30, "out": 16.00,
 "v_src": "/abs/broll_hands.mp4", "v_in": 2.5}
```

Чтобы вставить перебивку в середину реплики — **разрежь клип на три**: до, перебивка,
после. Границы бери по словам из транскрипта, иначе разрыв будет слышен.
`mute: true` глушит звук клипа (перебивка со своим паршивым звуком).
Если исходник перебивки короче нужного куска, `verify` предупредит — картинка замрёт.

Пути в `src` — абсолютные.

## Графика и карточки

Рисуются libass в том же проходе, что и субтитры: ни отдельного рендера, ни единого
внешнего файла. Время задаётся в секундах **исходника** (как в транскрипте) — движок
сам пересчитает его на смонтированный таймлайн, а карточку, попавшую в вырезанный
кусок, пропустит с предупреждением.

**Два правила, добытые на реальном материале — не нарушай их:**

1. Полноэкранная карточка — это **затемнение поверх живой картинки**, а не чёрный
   слайд. Врезка с крупным текстом на чёрном читается как заставка из нулевых.
   Сплошная заливка есть, но только по явному запросу: `"opacity": 1.0`.
2. Всё, что с подложкой, ставится **по замеру лица**, а не по константе. Любая
   «безопасная» доля высоты рано или поздно ложится говорящему на подбородок.
   Движок сам считает свободную полосу (`ve_reframe.face_band`) и выбирает: под
   лицом, если субтитры оставили место, иначе над лицом.
3. Счётчики «1/4, 2/4…» существуют, но по умолчанию **не включай** — заказчик
   назвал их колхозом. Только по явной просьбе.

```
$VE cards edl.json --auto     # найти перечисление и пронумеровать
$VE render edl.json --cards   # то же на лету
$VE shorts FILE --cards
```

| тип | что это | ключи |
|---|---|---|
| `full` | полноэкранная врезка: картинка закрыта, звук дубля идёт | `text`, `bg`, `fg`, `size`, `wrap` |
| `counter` | бейдж «2/4» в углу | `text`, `bg`, `fg` |
| `lower` | нижняя плашка | `text`, `y` (доля высоты, по умолчанию 0.56) |
| `pop` | всплывающее слово с отскоком | `text`, `y`, `size` |

```json
"cards": [
 {"type":"full","at":16.74,"dur":1.35,"text":"НО НА САМОМ ДЕЛЕ","fg":"#FFD400"},
 {"type":"counter","at":25.29,"dur":1.75,"text":"1/4"}
]
```

`--auto` ищет в расшифровке порядковые зачины («во-первых», «во-вторых», `first`,
`second`…) и вешает на них счётчик с автоматически посчитанным итогом. Если
перечисления нет — честно ничего не делает.

Субтитры рисуются **поверх** карточек (слой 4 против 1–2): на полноэкранной врезке
зритель продолжает читать. Плашку `lower` держи выше 0.6 — ниже начинается полоса
субтитров, и они перекроют друг друга.

## Субтитры

Строятся из word-level ASR, слово подсвечивается ровно тогда, когда произносится.

| стиль | вид | под что |
|---|---|---|
| `chip` | Montserrat ExtraBold, белый капс, активное слово в заливке со скруглением | Reels/Shorts — основной |
| `hormozi` | крупный Arial Black, 3 слова, активное слово жёлтым | Reels/Shorts/TikTok |
| `karaoke` | заливка слова по мере речи | клипы, музыкальное |
| `standard` | обычный субтитр, 8 слов, снизу | YouTube, интервью |
| `minimal` | мелкий, плашка, без обводки | корпоратив, доклады |

Переопределяется в `captions`: `font`, `size`, `max_words`, `marginv` (доля высоты;
**меньше — ниже**). У `chip` дополнительно `pill` (цвет заливки, по умолчанию
`#4B41A5`), `pill_pad`, `pill_r`.

### Как устроен `chip`

Шрифты лежат в `automontazh/fonts/` пакета и подсовываются libass через
`subtitles=...:fontsdir=`.
Ширина заливки **измеряется Pillow по тому же TTF**, которым рисует libass, — иначе
она не сядет по слову. Текст строк рисуется один раз на чанк, двигается только
заливка: это читается как проезд, а не как мигание.

Две ловушки, уже стоившие отладки:

- В стиле ASS надо писать **семейство из файла** (`Montserrat`), а не «Montserrat
  ExtraBold». Иначе libass молча берёт другой начерк, и измеренная заливка
  оказывается втрое шире слова. Держи по одному начертанию на семейство.
- Отрисовка `chip` живёт в отдельном `ve_chip.py` **намеренно**: ASS-теги полны
  обратных слэшей, и правка их через `str.replace` в патче однажды съела
  экранирование (`{\an7` превратилось в `{n7`), после чего субтитры не отрисовались
  вовсе. Правь этот файл целиком, а не точечными заменами.

Новый шрифт: положи статический TTF в `automontazh/fonts/` пакета. Вариативные
шрифты не годятся —
libass берёт из них начертание по умолчанию (Regular). Статический экземпляр
вытапливается из вариативного через `fontTools.varLib.instancer` (пример —
в истории скилла: `wght=800`).

## Звук (`--voice`)

```
$VE voice FILE               # замерить и показать, что будет сделано
$VE render edl.json --voice  # применить
```

Та же логика, что с картинкой: **сначала замер, потом решение**. И тот же честный
вывод — он важнее самой цепочки.

**Не начинай с шумодава.** У нормально снятого на телефон монолога сигнал/шум
обычно 40+ дБ: чистить нечего. Реальная беда почти всегда в тембре — задранный низ
(бубнёж) и провал в 2–8 кГц (нет разборчивости). Это лечится эквалайзером, а не
нейросетью. На тестовом ролике: с/ш 47 дБ, но 4–6.3 кГц на −44 дБ — после коррекции
+18.9 дБ в этой полосе, и запись стала звучать принципиально иначе.

Что меряется и что из этого следует:

| замер | решение |
|---|---|
| спектр речи по 12 полосам | правка = разница с целевой кривой голоса, зажим −8…+12 дБ |
| шум в каждой полосе | полосу не поднимают выше `−50 dBFS` остаточного шума |
| сигнал/шум | >35 дБ — шумодав **не включается**; ниже — `afftdn` |
| спад после слова | оценка реверберации; эквалайзером не лечится, нужен нейродереверб |

Дальше по цепочке: `highpass=80` (рокот), `firequalizer` с измеренной кривой,
де-эссер (после подъёма верха шипящие лезут), компрессор 3:1.

Полосы **ниже 160 Гц можно только резать, никогда не поднимать** — там рокот, а не
голос. Формула «цель минус измеренное» об этом не знает и однажды предложила
+3.6 дБ на 60–100 Гц.

`--strength 0.5` вдвое мягче. Профиль — в `.ve/NAME.voice.json`.

## Автоулучшение картинки (`--grade auto`)

Не пресет «сделай красиво», а коррекция, выведенная из замеров конкретного файла:

```
$VE enhance FILE            # показать замеры и что будет сделано
$VE autocut FILE --grade auto ...
$VE render edl.json --grade auto
```

Что меряется по кадрам (OpenCV, ~120 сэмплов) и что из этого следует:

| замер | решение |
|---|---|
| чёрная точка (p0.1) | тянем её в 0 — снимает «молочность», это обычно главный выигрыш |
| % выбитого в белое | если >15%, света **не поднимаем**: там уже нет данных |
| баланс белого | по светлой неклиппированной полосе (стена), **не** по средним тонам — их забивает кожа и коррекция уходит в синеву. Правим на 60%, зажим ±7% |
| насыщенность | цель 30/255, потолок ×1.32 — выше кожа начинает светиться красным |
| резкость (Лапласиан) | <30 → ×1.0, <70 → ×0.8, <140 → ×0.5, иначе не трогаем |
| временной шум | >2.5 → hqdn3d, >6.5 → сильнее |

Порядок важен: шумодав идёт **до** масштабирования (на родном разрешении), контурная
резкость — **после**, иначе давим уже размазанное и точим шум.

`--strength 0.5` ослабляет всё вдвое, `1.5` усиливает. Профиль кэшируется в
`.ve/NAME.enhance.json` — там же видно, какие числа получились.

Апскейл 720→1080 не добавляет деталей, но площадки лучше относятся к 1080×1920.
Делай, когда просят «подтянуть», и честно говори, что это не восстановление деталей.

## Вертикаль и автореврейм

Для Reels/Shorts: `--width 1080 --height 1920 --fit crop`.

Статичный `crop` режет по центру и теряет говорящего, если он смещён или ходит.
Поэтому по умолчанию для вертикали включай **автореврейм** — кроп едет за лицом:

```
$VE autocut FILE --width 1080 --height 1920 --fit crop --reframe --captions hormozi
$VE render edl.json                    # реврейм уже записан в EDL
$VE render edl.json --reframe          # или включить на лету
$VE render edl.json --no-reframe       # или выключить
```

Как это устроено: `ve reframe FILE --to 1080x1920` прогоняет YuNet (OpenCV,
232 КБ, лежит в `automontazh/models/` пакета) на 6 кадрах в секунду, берёт лицо,
ближайшее к
предыдущему положению — с поправкой на размер, чтобы не перескакивать на того,
кто просто крупнее. Трек чистится медианой, потом гистерезис с зоной
нечувствительности 4.5% ширины кропа: мелкое дрожание игнорируется, реальное
смещение — плавный проезд, а не рывок. Голова ставится по верхней трети кадра.
Трек кэшируется в `.ve/NAME.reframe_WxH.json`; в рендере его отыгрывает
`sendcmd`, покадрово двигая `crop`.

Если лицо найдено меньше чем в 25% кадров, движок честно говорит об этом и
откатывается на статичный центральный кроп. Проверь такой ролик глазами через
`frames` — возможно, кадрировать надо вручную через `"vf"` на клипе.

Реврейм не нужен, если снято сразу вертикально: исходник уже нужного
соотношения, `crop_box` это видит и возвращает кадр как есть.

## Когда всё-таки смотреть картинку

`$VE frames FILE --at 12.5,30,45` или `--start A --end B -n 12`. Обращайся, когда:
выбираешь между визуально разными дублями; проверяешь, в кадре ли человек; ищешь
момент для b-roll; финально принимаешь работу. Не сканируй видео целиком — это
именно то, чего вся конструкция избегает.

Ещё: `$VE silence FILE` — карта мёртвого воздуха, `$VE scenes FILE` — смены планов
(полезно для отснятого с нескольких камер или для поиска склеек в чужом материале).

## Ограничения — говори о них честно

- Один говорящий на дорожке; диаризации нет.
- Реврейм ведёт лицо, а не тело: если человек отвернулся или вышел из кадра,
  кроп замирает на последнем известном месте.
- B-roll не подбирается сам: если нужен, ты сам ставишь клипы в EDL.
- Выбитые в белое света (окно за спиной) **не восстанавливаются** ничем — только
  роллофф, чтобы переход не резал глаз. Говори это прямо, не обещай магии.
- Реверберацию («хвост комнаты» на голосе) эквалайзер не убирает. Нужен
  нейросетевой дереверб — в движок пока не встроен.
- `verify` ловит технику, а не смысл. Смысл проверяешь ты по транскрипту.
- ASR ошибается на именах, терминах и жаргоне — там, где `⚠`, перепроверь по кадру.
